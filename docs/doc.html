Introduction

LXON is a serialization format, used to store data into readable, non verbose text. That text can then be parsed, extracting the data back into computer workable objects.

Its primary use cases are:

  • Storing data on files locally in order to load them (such as game saves, settings, config files, etc.)
  • Uploading data to a local HTTP server to allow for data exchange or general communication between two apps.
  • Creating request and response packets for modern Web APIs where the size, feature and type benefits far outweigh the need for a globally, easily accessible data language. This is very rare.

Pros

  1. Support for a lot of different container and value types, allowing for better data representation.
  2. Requiring little syntax, resulting in smaller, less verbose files.
  3. Requiring little syntax, making it faster and more enjoyable to write.
  4. Heavily based on JSON, where someone who understands the JSON fundamentals could easily pick up the basics of the format within a short explanation.
  5. Very intuitive syntax rules, having been refined by me personally (Nick Jasper) for countless months.
  6. Low floor, high ceiling: The basics of the format are what's used 90% of the time, the more advanced stuff (colors, maps, etc.) are only used in specific scenerios and can be ignored in most cases.
  7. A LXON file can be very spaced out and readable, or a single, ultra-compressed line of data, or anywhere in between.

Cons

  1. More syntax rules, upping the barrier to entry if wishing to learn and remember the entire format or to read/edit complex LXON files.
  2. Less of an industry standard then the more limited alternatives like JSON, YAML and (god forbid) XML.
  3. The whole entire documentation is written by me, a human, with no usage of AI other then for searching up specific terms. This means it could be harder to read at times, but at least there's personality in it.

Analogy

The !! cont.root ! root object ! is a store.

Inside the store, we can add items that clients can purchase or browse. Those items are !! vals ! values !.

We organize those items using boxes, shelves, rooms, or within the root itself. Things that can hold groups of items together, those are !! containers ! containers !. We can even put containers inside of other containers, known as nesting (nested containers).

In order to find the items or containers inside the parent container, we assign them labels. The labels are the !! keys ! keys !, used by !! containers.objects ! objects !, !! containers.maps ! maps ! and !! containers.doodads ! doodads !. !! containers.arrays ! Arrays ! use invisible and automatically assigned labels known as indexes.

Supported Types

LXON supports 2 main features, 4 container types, 8 key types and 12 value types, along with hundreads of color types.

Features

  • !! other.comments ! Comments ! #
  • !! other.escape ! Escape Sequences ! \

Containers

  • !! conts.obj ! Object ! { with }
  • !! conts.arr ! Array ! [ with ]
  • !! conts.map ! Map ! ( with )
  • !! conts.doo ! Doodad !

Keys

  • !! keys.str ! String ! "
  • !! keys.bool ! Boolean ! :
  • !! keys.num ! Number !
  • !! keys.date ! Date ! &
  • !! key.mon ! Monetary ! $
  • !! keys.bind ! Keybind ! @
  • !! keys.col ! Color !*Key can only be one color type
    • SRGB Color # or ;
    • Linear Color = or ;=
    • Preset Color /*Complex type declaration
    • Linear Preset Color /*Complex type declaration
  • !! keys.enum ! Enum ! *

Values

  • !! vals.text.full ! Full String ! "
  • !! vals.text.str ! String ! ` or ^
  • !! vals.text.char ! Char ! '
  • !! vals.bool ! Boolean ! $ or !
  • !! vals.num ! Number !
    • NaN -
    • +Infinity % or +%
    • -Infinity-%
  • !! vals.date ! Date ! &
  • !! vals.mon ! Monetary ! $
  • !! vals.bind ! Keybind ! @
  • !! vals.col ! Color !
    • !! vals.col.spaces.srgb ! SRGB Color ! # or ;
    • !! vals.col.spaces.lin ! Linear SRGB Color ! = or ;=
    • !! vals.col.spaces.profile.reg ! Profiled Color ! /*Complex type declaration
    • !! vals.col.spaces.profile.lin ! Linear Profiled Color ! /*Complex type declaration
  • !! vals.enum ! Enum ! *
  • !! vals.bin ! Binary ! ?
  • !! vals.special ! Special !
    • Null ~
    • Undefined _
