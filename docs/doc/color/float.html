Definition and Types

A 16 bit color value allows for storing color values with 256x more precision and depth than an !! val.color.8 ! 8 bit color !. It allows for storing colors with a 16 bit depth per channel, totalling 8 bytes (64 bits) over 4 channels (red, green, blue, alpha/opacity).

This group supports 4 color spaces:

  • RGB Color##
  • Linear Color==
  • P3 Color//
  • ProPhoto///

Syntax

All 16 bit colors use the same syntax rules as !! val.color.8 ! 8 bit colors !, with a few crucial differenc.

Following the type declaration (see above), all succeeding hexadecimal characters (0 to 9 and "a" through "f") are used to store the color data.

Unlike 8 bit, which requires each hex character to be one after the other, uninterrupted, 16 bit color allows and even encourages seperating each channel with a space, forming hex clusters. All 16 bit colors are formed of 4 hex clusters. The clusters are assigned to the red, green, blue and alpha/opacity channels respectively.

The best way to end a color is using a backtick` or newline, although the color ends when all hex clusters are read. The first backtick following a 16 bit color is always skipped, regardless if it was used to terminate the color or not.

Examples of 16 bit color usage: 

{
yellow RGB: ##ffffeeee0000ffff

magenta Linear: ==ffff 0 ffff

blue P3 color: //0 0 ffff

black ProPhoto: ///0 0 0

array:[ ##ffff` ==0 0 0 0` //f23e 192b 900e

Channel Skipping

If a color ends prematurely, the color still constructs itself based on the data it managed to parse, setting the remaining channels to their default values (red: 0%, green: 0%, blue: 0%, alpha: 100%).

As consequence, if a color happens to have an empty color channel, writing of that data can be skipped. This can be very useful to save characters, especially for skipping the alpha channel which is usually 100% opaque either way.

Also, after a space, the parser expects to begin reading the next channel. If, however, that hex cluster is missing, and a second space is found instead, then the channel gets skipped altogether, using it's default value (0% for all except alpha which is 100%). You can therefore skip channels by doing a double or tripple space between clusters.

As a consequence of the strict spacing rules, it is easy to get mixed up. The best way to think about it is that every space means "end the current cluster and begin the next", similarly to what^is to a !! val.text.str ! string !.

Channel skipping examples (the keys are named after the colors, read comment): 

{
black: ##
red: ##ffff
orange: ==ffff 7000
yellow: ==ffff eeee
green: // ffff
blue: //  ffff
void: //   0
# ^^ black and 0% opacity
