Definition

An array is likely the second most used container type in LXON, following objects. It is container which can hold a group of values of same or differing type, serving to organize those values by index. It allows for duplicate values.

Syntax

To write an array, you must use its declaration character, the open square bracket [.

Afterwards, write each !! val ! value ! properly, ensuring to correctly terminate it before proceeding to the next one. Some values, such as !! val.text.full ! full strings ! cannot be terminated on the same line and require a newline altogether. The most reliable way of terminating a value is with a newline, which is supported for all value types.

Here are examples of arrays written on a single line: 

{
movies:[ `Jacob's Ladder` `The Shining` "Mulholland Drive

Multiline

As apparent in the example above, writing an object on a single line can easily make it become long and unreadable. It is at the developper's discretion when they chose to represent an array's values on multiple lines or on a single line.

When writing a value on a newline, simply ensure to add 1 additionnal indentation compared to the line preceding it. Indentation MUST use tab characters, space characters aren't taken into consideration for indentation and are instead appended at the start of the key.

Termination

Arrays are mainly terminated when the next line doesn't have the required indentation level. This is the most common way to terminate arrays.

Here are examples of indentation terminated arrays: 

{
arr1:[ "value
arr2:[
	"value

Rarely, usually only when writing a LXON data inline (all on one line), the indentation termination is impossible to achieve. This is because the next key or value external to the array isn't on a newline, but on the same line following the array.

In this scenerio, you should use the array termination symbol, a closing square bracket ].

Here are examples of ways to terminate arrays using the termination symbol (read !! other.comments ! comments ! as some of the examples showcase common mistakes): 

{
# THIS IS CORRECT
arr1:[ 1 4 ] arr2:[ $ 5 ]
arr3:[
	`value` ]
arr4:[
	"value
	]

# THIS IS A MISTAKE
# ] gets read as the next key, 
# its indentation is wrong
arr5:[
	'v
]

Empty Arrays

The most straightforward way of creating an empty array is to terminate it as soon as you create it (arr1 in the example below).

However, arrays are also terminated if the next line has improper indentation (arr2 in the example below).

Here's an example showcasing all methods of creating an empty array as shown above: 

{
arr2: [
arr1: []
