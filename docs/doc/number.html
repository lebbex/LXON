Definition

A number is a value type which can hold any numerical value, including decimal numbers, scientific notation, as well as certain constants. Numbers are self-declared and require no type definition.

Numbers cannot contain anything other then the number, and they end at the first non-numerical character found. It is recommended to terminate numbers using spaces or newlines in cases where the LXON might be manually edited later.

Syntax

Integral Part

To write a number, you just write the number as is, with a negative sign - in the case of a negative number, or an optional plus sign + in the case of a positive number. 

{
pos: 500
neg: -50
xtr: +50

Decimal Part

To write the decimal part of the number, write a dot ., then write the decimal part. 

{
dec1: 0.2
dec2: -15.32
__pi: 3.1416
posi: +10.5

If a number's integral part is 0 (zero), meaning there's only a decimal part, then the integral part can be skipped altogether and only the decimal part be written. 

{
valid: .592
extra: -.5
wrong: .623.59
# This last value wouldn't parse correctly

Scientific Notation

Scientific notation is also supported for numbers, and is simply written by appending e right after the number, as well as a optional sign and the exponent number.

Scientific notation is not compatible with !! val.num.percent ! percentage notation !. 

{
num1: 1.3e5
num2: -2.6e-3
num3: .5e+10

Percentage Notation

Numbers can also be represented as percentages, and are simply written by appending % right after the number. This divides the final number by 100 when parsing. It is mostly for aesthetic and communicating the scope of the number to readers of the serialized data.

Percentage notation is not compatible with !! val.num.sci ! scientific notation !. 

{
master: 80%
music: 90.4%
world: 110%
voice: .2%

Static Numbers

There are three static values for numbers, each of which self-declared and requiring no type definition:

  • NaN - *Must be followed by a non-numerical character
  • Positive (+) Infinity +%
  • Negative (-) Infinity -%
{
not a number: -
pos infinity: +%
neg infinity: -%

Important Precisions

Infinity must be either +% or -%, since the percent symbol % isn't a type declarator itself. This frees up the percent symbol to potentially be used as a type declarator in the future.

The + and - symbols are type declarators, where the minus symbol also acts as a modifier on the number following it, inverting it. However, if there is no number following the symbol, the parser attempts to multiply a undefined value by "-1", which, in the case of JavaScript (the native implementation of LXON), returns NaN.

NaN's syntax was an unintended side effect that ended up becomming part of the LXON standard. Some parsers might support + as a declaration of NaN, however, for simplicity, NaN should always be represented as -.

To be sure that the value is properly interpreted, it is standardized to follow the minus symbol with either a space character or a newline. It will work however as long as what follows it cannot be interpreted as a number (see regular/decimal number syntax above).
