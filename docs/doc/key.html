Outline

Keys are labels attached to chunks of data (values) that allow for identifying, organizing and recuperating them.

They're used by !! containers.objects ! objects !, !! containers.maps ! maps ! and !! containers.doodads ! doodads !, all of which using different key types (see below). !! keys.single ! Doodad keys ! are the only keys that do not require a colon following the key.

Regular Keys

Regular keys are used by !! containers.objects ! objects !. They can only be text with a specific format and syntax. Many characters aren't allowed, such as starting whitespace and colons. !! other.escape ! Escape characters ! (\n, \:, etc.) also aren't supported. You can create an empty key by simply typing a colon directly.

Usage

To use a regular key, simply create a !! containers.object ! object ! and write your key as is. Terminate the key using a colon. Here's some example usage as reference: 

{
key1: "string

key2:{
	a: 10
	b: 20

key3:
	3key: "value

: "value's key is empty

Typed Keys

Typed keys are used by !! containers.maps ! maps ! and support keys of text and non-text types. Also, string keys are superior to regular text keys since they support escape characters, allowing starting whitespace and colons. All typed keys of a map must be of the same type, hence typed keys are homogeniously typed.

Here is a cheat sheet list of all typed key types and their respective declaration characters:

  • !! key.str ! String ! "
  • !! key.bool ! Boolean ! :
  • !! key.num ! Number !
  • !! key.date ! Date ! &
  • !! key.mon ! Monetary ! $
  • !! key.bind ! Keybind ! @
  • !! key.col ! Color !
    • SRGB Color # or ;
    • Linear SRGB Color = or ;=
    • Profiled Color /*Complex type declaration
    • Linear Profiled Color /*Complex type declaration
  • !! key.enum ! Enum ! *

Usage

To use a typed key, simply create a !! containers.map ! map ! and declare the key type using a respective declaration character (see above). Terminate the key using a colon.

For dates, it is reccomended to use double colons following the key. This is because dates themselves use colons to seperate the time components, and those colons take priority when parsing. Double colons also help with readability for date keys.

Here's some example usage of various values as inspiration: 

("
key\n1: "string

key2:('
	a: 10
	b: 20

key3:(
	3.2: "value
	-.4: "value

key4:(&
	2026-07: "value
	2026-07-01T12:30:: "value

key5:(*weapon
	sword: 42
	gun: 83
	hammer: 0

Single Character Keys

Single character keys are used by objects. They are single characters and do not require a colon as termination. !! other.escape ! Escape characters ! (\n, \:, etc.) are supported. You can type an empty key by typing the null character's escape sequence \0.

Characters containing escape sequences should be avoided though, as they can create ugly and confusing formatting. It should only be done for data that likely won't be read or editable by others.

Usage

To use a single character key, simply create a !! cont.doo ! doodad ! by using any character that isn't a declaration character when prompted for a value. This character will be your first key. Here's some example usage as reference: 

{
coordinates: x5.39 y-.12 z102.43

more coords: x291
	y1920 z5839

rotation: y0 p0 r0

empty key doodad: \0 "value
