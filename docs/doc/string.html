Definition

A string value is the most versatile and useful way of representing a string in LXON. It allows for storing any string imaginable, usually following !! val.text.str.inline ! inline syntax !, however with the option of !! val.text.str.mult ! multiline syntax !.

Inline

An inline string requires a backtick ` or caret ^ at the start, as type declaration. Everything until the terminator symbol or until the end of the line will be read as the string, accepting !! other.escape ! escape sequences ! and trimming no whitespace.

Chaining

When a caret ^ is used to terminate an string, it will not only mark the end of the current string value but also the start of a new one. This new string can be a !! val.text.str.mult ! multiline string ! if declared as such.

Escaping

Inline strings require !! other.escape ! escape sequences ! for the following characters:

  • Newline \n
  • Carriage Return \r
  • Backslash \\
  • Backtick \`

Whitespace

Although tab representation is supported, it is reccomended to replace them with \t. This allows for better visualization as well as a shortening of the visual length of the string. This does however come at the cost of an extra byte stored per tab, so this decision comes down to the developper.

Strings trim all trailing whitespace if terminated by the end of the line. Counter this by either using a terminator symbol, or replacing the last whitespace with its escape code (\s for space and \t for tab).

Multiline

To declare a multiline string, after the string declaration symbol (backtick ` or caret ^), immediately end the line. This will declare the string as potentially being a multiline string.

For every line of the string's value, ensure there's 1 additionnal indentation compared to parent's indentation, followed by a backtick `. Indentation MUST use tab characters.

The entire rest of the line will be read verbatim as the string, ignoring all !! other.escape ! escape sequences ! and trimming no whitespace.

Important

The declaration character MUST be followed IMMEDIATELY by the end of the line. If there's whitespace (space, tab, etc.) then the end of the line, it will fail to declare the multiline string, even though it looks identical to a multiline string declaration.

If a multiline declaration is failing, make sure there's no space after the initial declaration character.

Termination

The multiline string is terminated by either breaking this indentation rule or ommiting the required backtick ` on a line. When only forgetting the backtick and having properly used indentation, most parsers will likely throw an error, however many could silently fail.

Usage

Here's some example usage of string values as reference: 

{
key: `string`
ehh: `string

multiline: `
	`The choir sings, all maintain the same tempo.
	`The tempo rises, thundering into a roaring crescendo.
	`The thunder claps, the cymbals crash, the choir breathes.
	`The choir inhales and exhales at the rhythm of the orchestrator.
	`- God Waits for No Man (2026)
	`

array:[ `str1` `str2`
	`str3
	`str4^str5`
	`str6^str7^
		`This is the string contents of the 8th item of the
		`parent array. Each line is part of the same string.
		`This is the last line of the 8th string.
	`str9` `str10
