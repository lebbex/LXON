Definition

An object is the most used container type in LXON. It is based on the JSON object type, which is in turn based on the native JavaScript object type. It serves to organize values by simple yet limited !! keys.reg ! keys !. It doesn't allow for duplicate keys.

Syntax

To write an object, you must use its declaration character when prompted for a value. Objects have two type declarators:

  • Opening curly bracket {
  • Newline (The litteral end of line)

Afterwards, you must write key/value pairs.

To do so, first write a !! keys.reg ! regular key !, which is mostly just text with a couple conditions requiring to be met. The regular key terminates at the first colon :, which helps seperate the key from the value.

After terminating the key with a colon, write the !! val ! value ! properly, ensuring to correctly terminate it before proceeding to the next key. Some values, such as !! val.text.full ! full strings ! cannot be terminated on the same line and require a newline altogether. The most reliable way of terminating a value is with a newline, which is supported for all value types.

Here are examples of objects written on a single line: 

{
movie1:{ title:`Jacob's Ladder` year:1990 dir:"Adrian Lyne

movie2:{ title:`The Shining` release:&1980-5-23

Multiline

As apparent in the example above, writing an object on a single line often makes it hard to read. The standard way of writing LXON demands (for readable data) that objects containing more than one key/value pair use multiline for clarity.

When writing a key/value pair on a newline, simply ensure to add 1 additionnal indentation compared to the line preceding it. Indentation MUST use tab characters, space characters aren't taken into consideration for indentation and are instead appended at the start of the key.

Here are examples of objects written with multiline taken into account: 

{
album:
	title: "Skin
	artist: "Flume
	release: &16-5-27

	lead single:{
		title: "Never Be Like You
		feature:
			name: "Kai
			birth: 1990 male: !

Termination

Objects are mainly terminated when the next line doesn't have the required indentation level. This is the most common way to terminate objects.

Here are examples of indentation terminated objects: 

{
obj1:{ key: "value
obj2:
	key: "value

Rarely, usually only when writing a LXON data inline (all on one line), the indentation termination is impossible to achieve. This is because the next key or value external to the object isn't on a newline, but on the same line following the object.

In this scenerio, you should use the object termination symbol, a closing curly bracket }.

Here are examples of ways to terminate objects using the termination symbol (read !! other.comments ! comments ! as some of the examples showcase common mistakes): 

{
# THIS IS CORRECT
obj1:{ id: 4 } obj2:{ id: 5 }
obj3:
	key: `value` }
obj4:
	key: "value
	}

# THIS IS A MISTAKE
# It terminates the root object instead
obj5:{
	key: 'v
}

# This data is never read
# because the root was terminated above
key: "value"

Empty Objects

The most straightforward way of creating an empty object is to terminate it as soon as you create it (obj1 in the example below).

However, objects are also terminated if the next line has improper indentation (obj2 in the example below).

Since objects can be declared by a newline, you can even create an empty object by simply writing nothing as a value, a simple newline with improper indentation on the next line (obj3 in the example below).

Here's an example showcasing all methods of creating an empty object as shown above: 

{
obj3:
obj2: {
obj1: {}
