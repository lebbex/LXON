Definition

A keybind is a value type which can hold any string. The only difference is its slightly more complex syntax, and the fact it doesn't get parsed into a string. As such, it isn't a !! val.text ! text value !.

Its primary use, as the name implies, is to store keybinds. In any development environment that supports keybinds, it will get parsed into one, such as in Unreal Engine 5. However, in languages that don't, such as JavaScript, it will get parsed into an alternative. To continue with the JavaScript example, in that language, it gets parsed into a Symbol. In other languages or development environments that have no support for anything but string, it will get parsed into a custom object, allowing it to be distinguished to regular string.

If the project doesn't require keybind parsing, you can either chose to ignore this feature or use it for something else, such as codes. It is generally useful to have a string alternative that doesn't parse into string.

Syntax

A keybind requires the at symbol @ as type declaration. Every following character is treated as the contents of the keybind, until the first instance of either its terminator symbol (backtick), or another valid declaration character as show below:

  • Backtick ` (terminator symbol)
  • Caret ^ (!! val.text.string ! string ! declaration)
  • At Symbol @ (!! val.bind ! keybind ! declaration)

It is standardized however to use the backtick, and only use the other characters for !! val.bind.chain ! chaining ! other values after it. Like with raw strings, keybinds also ends at the end of the line, so trailing backticks aren't strictly required.

Chaining

Keybinds support value chaining, a feature which makes use of the rare characters which are unexpected to be present in a keybind, such as those stated above. These characters happen to be declaration characters for other types.

In order to make use of them, and save up on valuable space and syntax, typing one of those characters in a keybind terminates the keybind and declares the next value as having the type declared by the termination character.

These chains should only ever be made inside an !! containers.arr ! array !, as it is the only event where values are expected to follow eachother.

Here's some examples of keybind chaining in action: 

{
keys:[ @Up @Down @Left @Right` -40 23

key+str1:[ @Mouse Left` `string`
key+str2:[ @Mouse Right ^string`

Escaping

As a consequence of its increase in complexity, keybinds require !! other.escape ! escape sequences ! for the following characters:

  • Newline \n
  • Carriage Return \r
  • Backslash \\
  • Backtick \`
  • Caret \^
  • At Symbol \@

Here's some example usage of keybind escaping: 

{
newln keybind: @up\ndown

backs keybind: @left\\right

anpsd keybind: @front\&back

weird keybind: @lxon\@lebbex.com
# This last one ^ is
# likely a mischosen value type.

Whitespace

Although tab representation is supported, it is standardized to replace them with \t. This allows for better visualization as well as a shortening of the visual length of the keybind. This does however come at the cost of an extra byte stored per tab, so this decision comes down to the developper.

Keybinds trim all trailing whitespace if terminated by the end of the line. Counter this by either using a terminator symbol, or replacing the last whitespace with its escape code (\s for space and \t for tab).

Codes

Standardized keycodes are vital for offering !! val.key ! keybind ! compatibility accross systems and applications. If using keybinds for their intended purpose, which is to store device input keys, keycodes are a crucial part of removing the keybind names language barrier.

  • Click Left Mouse Left
  • Click Right Mouse Right
  • Click Middle Mouse Middle
  • Back Thumb Button 1 Mouse Back
  • Front Thumb Button 2 Mouse Front
  • (Any other mouse button is Mouse # where # is the unsigned integer button index)
  • Scroll Up Scroll Up
  • Scroll Down Scroll Down
  • Scroll Left Scroll Left
  • Scroll Right Scroll Right

Keyboard Codes

  • Letter keys are designated by their respective letter in uppercase. Example:
    • W W
  • Punctuation marks and symbols are all designated by their respective punctuation or symbol. Examples:
    • Semicolon ;
    • Equals =
  • Number keys (those above the letters, not numpad) are their respective number. Example:
    • 4 4
  • Numpad keys are Num followed by the respective number. Example:
    • Numpad 4 Num 4
  • Function keys (the row above number keys) are their respective F# name. Example:
    • F11 (Fullscreen) F11
  • Shift, Alt, Ctrl, Windows and Command are their respective name followed by nothing if designating any, followed by "Left" if designating only the left one, or followed by "Right" if designating only the right one. Examples:
    • Any Shift Shift
    • Left Shift Shift Left
    • Left Windows Key Windows Left
    • Right Command Key Command Right
