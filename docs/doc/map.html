Definition

A map is the more expansive version of the !! cont.obj ! object ! type. It uses typed keys over regular keys, which not only allows for non-text keys (such as numbers, booleans, dates, colors, etc.), but also allows for string keys with no limitations. You can then have keys that accept !! other.escape ! escaped characters !, allowing for newlines or colons within the key, or even tabs at the start of the key. It doesn't allow for duplicate keys.

Syntax

To write a map, you must use its declaration character, the open parenthesis ( when prompted for a value. The declaration then demands for a !! keys.typed ! typed key declaration !.

Here is a cheat sheet list of all typed key types and their respective declaration characters:

  • !! keys.string ! String ! "
  • !! keys.bool ! Boolean ! :
  • !! keys.num ! Number !
  • !! keys.date ! Date ! &
  • !! key.mon ! Monetary ! $
  • !! keys.bind ! Keybind ! @
  • !! keys.color ! Color !
    • SRGB Color # or ;
    • Linear SRGB Color = or ;=
    • Profiled Color /*Complex type declaration
  • !! keys.enum ! Enum ! *

Afterwards, you must write key/value pairs.

To do so, first write a !! keys.typed ! key ! with the chose type above, In all scenerios, the key terminates after the first colon :, except for !! keys.date ! date keys !, which require double colons ::.

After terminating the key with a colon, write the !! val ! value ! properly, ensuring to correctly terminate it before proceeding to the next key. Some values, such as !! val.text.full ! full strings ! cannot be terminated on the same line and require a newline altogether. The most reliable way of terminating a value is with a newline, which is supported for all value types.

Here are examples of objects written on a single line: 

{
movie1:(" title:`The Notebook` \nyear:2024

movie2:(' t:`Titanic` r:&1997-12-19

Multiline

As apparent in the example above, writing a map on a single line often makes it hard to read. The standard way of writing LXON demands (for readable data) that map containing more than one key/value pair use multiline for clarity.

When writing a key/value pair on a newline, simply ensure to add 1 additionnal indentation compared to the line preceding it. Indentation MUST use tab characters, space characters aren't taken into consideration for indentation and are instead appended at the start of the key.

Here are examples of maps written with multiline taken into account: 

("
album:
	title: "Black Silk
	artist: "Spooky Black
	release: &14-2-28

	lead single:(*field
		title: "Without U
		sample:('
			t: "Darkest Place
			a: "Woman's Hour
			r: &14-7-21 g:$

Termination

Maps are mainly terminated when the next line doesn't have the required indentation level. This is the most common way to terminate objects.

Here are examples of indentation terminated objects: 

{
map1:(" key: "value
map2:("
	key: "value

Rarely, usually only when writing a LXON data inline (all on one line), the indentation termination is impossible to achieve. This is because the next key or value external to the map isn't on a newline, but on the same line following the map.

In this scenerio, you should use the object termination symbol, a closing parenthesis ).

Here are examples of ways to terminate map using the termination symbol (read !! other.comments ! comments ! as some of the examples showcase common mistakes): 

("
# THIS IS CORRECT
map1:(" id: 4 ) map2:(' i: 5 )
map3:("
	key: `value` )
map4:("
	key: "value
	)

# THIS IS A MISTAKE
# It terminates the root map instead
map5:("
	key: 'v
)

# This data is never read
# because the root was terminated above
key: "value"

Empty Maps

The most straightforward way of creating an empty map is to terminate it as soon as you create it (map1 in the example below).

However, maps are also terminated if the next line has improper indentation (map2 in the example below).

Here's an example showcasing both methods of creating an empty map as shown above: 

{
map2: (
map1: ()

Usage

Feel free to temporarily skip all syntax documentation above and look through these examples if you're more of a pattern recognition/visual learner. However, it is very wise to be aware of the rules to avoid doing something that seems like it would work but doesn't.

Also, since maps are much more complex than !! cont.obj ! objects ! or !! cont.arr ! arrays !, it is highly reccomended to look into explicit syntax rules.

With that being said, here are additionnal map usage examples, for reference:
